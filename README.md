# Motion Design — portfolio landing

Статический сайт без сборки: `index.html` + `style.css` + `main.js`.
Three.js и шрифты подгружаются с CDN.

## Запуск локально

Модули ES не работают по `file://`, поэтому нужен любой локальный сервер:

    python3 -m http.server 5173 --bind 127.0.0.1 --directory /Users/mp/Desktop/Motion Site

и открыть http://localhost:5173

## Как это устроено

- Один экран скролла = одна смена слова (MOTION DESIGN → FOR → YOUR → PROJECTS),
  пятый экран — главное меню: лого уезжает вверх и «растекается» в струю жидкого хрома,
  сквозь пряди проходит заголовок FROM / VISION / TO / MOTION (одна прядь за буквами),
  слева вкладки WORK / CLIENTS / MANAGER / CONTACT, справа подпись, внизу SCROLL.
  Всё в `CONFIG.menu`: поза головы, ленты (ширина, радиус, глубина), материал, текст.
  Анимация идёт ровно за скроллом, без «прилипания»: остановился — осталось на месте.
  Последние 20% каждого экрана слово стоит неподвижно (`CONFIG.text.dwell`).
- Уходящее слово уезжает влево, размывается и рассыпается в частицы; новое въезжает
  справа и собирается из частиц (`CONFIG.dust`).
- Каждое слово подгоняется под ширину экрана (`CONFIG.text.width`), высота ограничена
  `CONFIG.text.maxHeight`.
- Лого кувыркается по всем трём осям по мере скролла (`CONFIG.tumble`), хроматическая
  аберрация только горизонтальная, при быстром скролле добавляется смаз.
- Пятый экран — главное меню (`CONFIG.menu`): лого растворяется в полупрозрачную струю
  жидкого хрома (три волнистые ленты), сквозь неё читается заголовок FROM / VISION / TO /
  MOTION (рисуется в canvas шрифтом Inter), слева вкладки WORK / CLIENTS / MANAGER / CONTACT,
  справа подпись.
- Шестой экран — WORKS: заголовок в стиле первых слов, подписи по бокам, карусель работ дугой
  в 3D с отражениями на полу. Управление: стрелки, точки, перетаскивание/свайп, горизонтальная
  прокрутка тачпада, клавиши влево/вправо. Пять карточек-плейсхолдеров: превью нарисованы CSS-градиентами
  (классы `.thumb-1 … .thumb-5`), названия и длительности в `index.html`. Чтобы поставить реальные
  работы, замени фон карточки картинкой/видео и повесь на кнопку Play открытие ролика.
- Седьмой экран — CLIENTS: веер вертикальных карточек клиентов с отражением. Лента сама медленно
  едет слева направо (`RIB.speed` в `main.js`), при наведении останавливается, у карточки поднимается
  панель с подробностями (на телефоне по тапу). Стрелки, точки, перетаскивание, клавиши влево/вправо.
  Восемь плейсхолдеров: рисунки CSS-градиентами (`.c-1 … .c-8`), тексты в `index.html`.
- Восьмой экран — CONTACT: заголовок, слева «Get in touch» и три стеклянные карточки, справа форма.
  Ссылки Contact (в меню и сверху) быстро «роняют» страницу вниз, WORK и CLIENTS ведут на свои экраны.
  Форма пока заглушка: `action="mailto:"`, подставь реальный адрес или бэкенд в `index.html`.
  Ссылка MANAGER пока заглушка.
- Верхние WORK / CONTACT прячутся только когда главное меню уже на месте, иконка слева видна всегда.
  Текущий раздел подчёркивается. Кнопка MENU справа сверху открывает оверлей со всеми разделами
  (Home, Work, Clients, Manager, Contact) с любого экрана; Esc закрывает.
- Карусель работ: расстановка карточек считается в экранных координатах с учётом перспективы
  и поворота, поэтому между карточками всегда остаётся зазор (`ARC` в `main.js`).

## Логотип

- **3D-модель** `assets/logo.glb` — основной вариант. Это модель из Tripo (исходник
  `~/Downloads/dragon+head+3d+model/*.fbx`), сконвертированная скриптом `tools/fbx2glb.py`
  через Blender: упрощение до ~90k граней, сглаживание, сжатие Draco (213 КБ вместо 4,9 МБ).
  Текстуры модели не используются, материал «тёмный хром» назначается на сайте.
  Пересобрать: `/Applications/Blender.app/Contents/MacOS/Blender -b --python tools/fbx2glb.py -- путь/к/модели.fbx`
- **Запасной вариант**: если в `main.js` поставить `logoModel: null`, объёмное лого
  строится прямо из `assets/logo.png` как «надутый» рельеф (`CONFIG.relief`).
- **Шапка**: `assets/logo.png`, чёрный логотип на прозрачном фоне (оригинал рядом,
  `logo-original.png`).

## Что крутить

- `main.js` → блок `CONFIG` сверху: размеры, материал, аберрация, частицы, скорость.
- `style.css` → переменные в `:root`: цвета; шрифт слов задан в `.word`.

## Отладка в консоли браузера

`window.__site` даёт доступ к `scroll`, `CONFIG`, `logo`, `material`, `caPass`, `layout`.
Например: `__site.material.roughness = 0.3` или `__site.scroll.target = 1.5`.
`__site.jump(1.4)` мгновенно показывает состояние на прогрессе 1.4 (0..3),
`__site.relayout()` пересчитывает размеры и частицы, `__site.debugHomes(0)` рисует
красным «домашние» точки частиц первого слова (проверка совпадения с буквами).

## Project Manager (раздел Manager)

Закрытая часть сайта: открывается поверх всего по кнопке Manager в меню или по ссылке
`…/#manager`. Файлы: `pm.js` (приложение), `pm.css` (стили), `pm-config.js` (адрес бэкенда).

**Роли.** Владелец создаёт проекты (бриф, дедлайн, тип, приоритет, клиент), назначает
исполнителя, кладёт файлы и правит бриф. Исполнитель заходит под своим email и паролем, видит
только свои проекты, читает бриф, скачивает файлы и отмечает галочками «получил», двигает процент
и статус (Brief received → Assets downloaded → In progress → Review → Completed), пишет в чат
проекта с вложениями. Разделы: Projects, My tasks, Calendar, Team (владелец добавляет
исполнителей и выдаёт им email/пароль), Messages, Settings.

**Бэкенд: Supabase.** Данные живут в Supabase и обновляются у всех в реальном времени:
- `supabase/schema.sql` — таблицы, права доступа (row level security), приватное хранилище
  файлов `project-files`, живые обновления. Запускается один раз в Supabase → SQL Editor.
- `pm-config.js` — Project URL и публичный ключ (publishable). Они не секретные: доступ к
  данным ограничен правилами в базе.
- `api/users.js` — серверная функция Vercel, через которую владелец создаёт и удаляет аккаунты
  исполнителей. Ей нужны переменные окружения в Vercel: `SUPABASE_URL` и
  `SUPABASE_SERVICE_ROLE_KEY` (секретный ключ, только на сервере, в код не попадает).
- Первый созданный аккаунт автоматически становится владельцем. Публичную регистрацию в
  Supabase (Authentication → Providers → Email → Allow new users to sign up) лучше выключить:
  аккаунты исполнителей создаются из раздела Team.

**Демо-режим без бэкенда.** Если в `pm-config.js` убрать значения или в консоли браузера
выполнить `localStorage.setItem('pm.demo', '1')`, менеджер работает локально с демо-аккаунтами
`alex / motion2026` и `jordan / creator2026` (данные только в этом браузере).

## Выкладка (GitHub → Vercel → домен)

1. Репозиторий уже инициализирован в этой папке; отправить его на GitHub:
   `git push -u origin main` (при запросе логина: имя пользователя GitHub и токен вместо пароля).
2. Vercel → Add New → Project → импорт репозитория → Framework «Other», без команды сборки →
   Deploy. В Settings → Environment Variables добавить `SUPABASE_URL` и
   `SUPABASE_SERVICE_ROLE_KEY`, затем Redeploy.
3. Settings → Domains → добавить домен (если он занят другим проектом Vercel, подтвердить перенос).
4. В Supabase → Authentication → URL Configuration → Site URL указать адрес сайта.

Папки `source/`, `tools/` и README в деплой не попадают (`.vercelignore`).
